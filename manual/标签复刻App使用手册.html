1. 它做什么

给一张已有标签的照片，App 把上面的内容"读出来"重新排成 ZPL，让斑马打印机打出一张新的。 不是识别文字抄下来，而是复刻版面：表格线、条码位置、文字字号都要还原。

拍照→四点标定→透视矫正→ 条码 + OCR + 框线→ZPL→打印
识别结果分三类要素：一维码/二维码、文字、框线。 结果页里每条都能单独改内容、改码制或删除，改完 ZPL 立即跟着变。

2. 五步上手

  1. 对准拍摄：把标签四边放进绿色取景框，尽量占满画面。底部点拍照识别； 已拍好的照片走右侧相册。
  2. 点四个角：进入标定页后，按 ①→②→③→④ 顺序依次点图片上标签的四个角， 点错了就拖动圆点微调——拖的时候旁边会浮出放大镜，看得清有没有压线。
  3. 矫正并识别：点右下绿色按钮。App 先把斜拍的照片拉成正视图，再识别。
  4. 核对结果：白纸预览上会用彩色框标出识别到的位置；下面列表逐条列出要素。 有错就点改修正，多余的点✕删掉。
  5. 打印：切到底部打印机选设备（老机走经典蓝牙 SPP，ZD421 这类走 BLE）， 首次建议先打一张测试页。
易错点：标定页不是"拖住小圆点才能动"，而是点图片任意位置就放一个角点。 只拖一个角、其余三个不动，出来的就不是你要的区域——必须四个角都落到位。

3. 界面逐页说明

3.1 拍照页

模板 chip决定 ZPL 画布尺寸。模板1 60×40、模板2 76×70、自定义 在打印机页填宽高。识别前选好，识别后再切换会按新尺寸重排。
取景框只是参考线和"对齐提示"，不裁像素；识别范围由第 2 步的四点决定。
拍照识别调系统相机拍一张，立刻进标定页。
相册选已有照片（现场补拍不用跑回机器）。
跑内置样图（自检）不接相机也能验证整条链路，排查"是相机问题还是算法问题"。

3.2 四点标定页

① → ④ 点按点一下图片放一个角点，顺序是左上、右上、右下、左下；点满四个后第 5 下回到 ①。
拖圆点微调。拖动时会校验四点是否交叉/凹陷，非法会提示"请重新点"，不会白算一次透视。
放大镜132dp 方形视窗、3× 放大，直接从原图裁局部（不是放大屏幕像素），靠近顶部会自动翻到下方。
自动预填让算法自己找标签轮廓。背景复杂时不靠谱（纸箱场景会框到整个画面），所以默认不自动跑，只留按钮。
重置四角回到"四边内缩 8%"的默认框，重新点。
矫正并识别透视变换 → 条码 → OCR → 框线 → 排版 → ZPL，约 8~12 秒（含 OCR）。

3.3 结果页

预览上的框色含义：黄框=框线（表格线/外框）、绿框=条码、灰框=文字。 "完成：N 个要素，M 个错误"里，错误指放不下/数据不合规这类必须处理的问题，正常是 0。

模板三个 chip 可随时切换，预览与 ZPL 同步重排。
含文字 OCR / 仅条码只想复刻条码内容时切"仅条码"，省时间也不会带入错字。
基准=label表示位置以整张标签为基准（另有点位基准，用于只贴小区域的场景）。
重新识别 / 调四角 / 重拍顶部三个按钮对应三种返工：换算法参数、重标四点、重新拍。

3.4 编辑要素

点列表里的改弹出此窗。上面是码制（Code 128 / Code 39 / EAN-13 / 二维码…），下面是内容。 条码的数据原样下发给打印机，App 不做补位、不算校验位、不改大小写——要改就改这里的原文。

唯一例外：EAN-13 / UPC-A / 交叉25 这类只收数字的制式，会在识别阶段就把非数字字符过滤掉并给出警告， 保证"预览 = 日志 = 下发给打印机"三者一致。

3.5 打印机页

标签纸尺寸按整张纸的实际毫米数填（不是可打印宽）。203dpi 下 8 点/mm：76mm → ^PW608。
经典蓝牙 SPP要在系统蓝牙里先配对。ZR668 / ZT 系列走这条。
低功耗蓝牙 BLE不用配对，点"扫描附近打印机"。ZD421 这类只开 BLE 的机器走这条。
启动时自动连这台车间每天开机就打印的场景，省掉每次重连。
打印测试页验通道。纸张出来但内容不对，先看尺寸是不是填错。
校准（换纸后）下发 ~jc^xa^jus^xz，让打印机重新测纸。
同一条蓝牙链路同一时间只能被一台手机占用。BLE 打印机被别的手机连着时，这里会一直连不上—— 先把那台手机的 App 断开。

4. 识别原理（框线为什么难）

条码和文字靠现成引擎（Zebra AI Data Capture + PP-OCR），框线只能自己算： 它是几条细直线，斜一点就"消失"。

问题：透视矫正之后，印刷表格线仍然斜 2~6°。

一条 8 点厚、1600 像素宽的横线斜 3°，在单独一行里只剩约 8/sin3° ≈ 150px 连续墨迹—— 只占整宽的 9%。旧算法判据是"某一行最长墨迹段 ≥22% 图宽"，于是 4 条表格线全漏； 反过来，纸箱、托盘那些连续暗行满足条件，纸上打出一堆乱框。实测旧版一张图只出 1~2 条错线，要素数多达 71 个。

现在的做法（Hough 找线）

① 取墨迹自适应阈值（局部均值 −10），抗反光抗阴影，比全局阈值稳。
② Hough 累加在 (±10°, 0.5° 步长) 角度上累加 rho = y − tanθ·x。 同一根线无论斜多少、中间断多少，都会汇到同一个峰上。横线和竖线分开累加（同一张图左竖框 −7.3°、右竖框 +4.9°）。
③ 定端点每个峰按 rho 收像素，取最长连续段当线段。不用分位数——条码、反光、纸边这些孤立墨点会把跨度拉宽两三百像素。
④ 校验沿线段垂直方向采样：线芯要比两侧暗 ≥12，两侧都要亮于本图纸面亮度。 纸边/折痕的特征是"线芯并不比两侧暗"，正好被这条挡掉。
⑤ 聚成表格按中线位置合并（同一根线被不同角度检出时 rho 会差二十几像素，只比 rho 合不掉，一条线会变三条）， 再聚簇、剔掉贴图纸边缘的那条、补齐缺失的左右边框。
⑥ 排除条码区条码上下沿是又长又黑的假横线，与条码框重叠超 50% 的线一律剔除。

实测数据（14 张不同背景的现场照片）

结果张数说明
精确 4 横 + 2 竖（与图纸真值一致）11纸箱、木桌、托盘、白纸各种背景，单张耗时 420~590ms

项目值备注

模板160 × 40 mm—

6. 常见问题

现象原因处理
拍照页底部提示"文件读不到"Android 分区存储不允许读 /sdcard/Download用相册选图；自动化测试把文件推到 App 自己的 files 目录
校正出来的不是我要的区域只拖了一个角，其余三个还是默认框四个角都点到位（①→④），再点"矫正并识别"
框线少一条 / 多一条少：那张被反光截断或贴纸边；多：条码上下沿或纸边被当线先在结果页点 ✕ 删多余；反复出现就回到"调四角"重新标定
自动预填框到整个场景背景是纸箱/托盘，白纸边界被背景干扰手动点四个角，不要用自动预填
条码打得扫不出码制发错（EAN-13 被当 Code128 估宽）或模块宽被压小结果页点"改"确认码制；别手动改内容位数
打印出来文字重合/糊字号按 ASCII 比值算，汉字实际占 1 em 宽，溢出后打印机把字挤着叠印缩短该行文字，或换更宽的模板
经典蓝牙连不上（read failed）打印机是 BLE 配对，没有 SPP 串口服务记录改用 BLE 通道；或让打印机把 bluetooth.le.controller_mode 设为 both/classic 后重配
BLE 扫描不到任何设备缺 BLUETOOTH_SCAN 权限（不报错，静默无回调）在系统设置里给 App 蓝牙权限；或用"手填 MAC"直连
打印"成功"但纸上没内容没连打印机时是干跑；或上次的作业还挂在队列里先打测试页确认通道；验收要拍新出纸的照片比对

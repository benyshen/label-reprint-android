# V1.6 版本记录（2026-10-20）

**打印机连接从结果页搬进独立设置页，并新增低功耗蓝牙（BLE）通道。** 识别/排版逻辑未动。

---

## 1. 为什么要单独一页

V1.5 之前，打印机那坨东西（状态灯、实时状态、已配对设备 chip、刷新/重连）全塞在结果页底部。
两个问题：

- **结果页被撑爆**：结果页的第一屏应该是"照片 + 要素 + 打印按钮"，被设备列表一挤，
  「打印这张标签」和「重拍」就滚出屏幕了；
- **一条列表装不下两条链路**：经典蓝牙和低功耗蓝牙是**两条物理链路**，
  能不能连、要不要先配对、扫不扫得到全不一样。混成一行 chip，用户看到 ZD421 没出现
  就会以为打印机坏了 —— 其实它压根不在系统配对表里，只在 BLE 广播里。

现在：结果页只留一条窄栏（灯 + 「已连接 ZR668 · 就绪」+「打印机」按钮），
点进去是独立页，分「经典蓝牙（SPP）」和「低功耗蓝牙（BLE）」两栏。

## 2. BLE 支持是怎么做的

**关键前提：原来的 ZSDK jar 太老，根本没有 BLE。** `ZSDK_ANDROID_API.jar`（2018 版，490 KB）
里只有 `com.zebra.sdk.comm.BluetoothConnection`（经典 SPP），没有 `btleComm` 包 ——
这就是为什么这个 App 之前只能连 ZR668 这类老机。voice-print-android 用的是 2026 版（576 KB），
里面有完整的 `com.zebra.sdk.btleComm.*`，直接换过来即可（两边的 Jackson 2.17.2 依赖一致）：

```
app/libs/ZSDK_ANDROID_API.jar              ← 换成新版（含 btleComm）
app/libs/ZSDK_ANDROID_API-2.14-noBLE.jar.bak  ← 旧包留档，回退只需换回来
```

链路选择在网关里**只判定一次**，不让两条通道互相回退（互相回退会掩盖真正的错误）：

| 目标串 | 通道 | 要不要先配对 |
|---|---|---|
| `BT:AC:3F:A4:F2:56:2F` | `BluetoothConnection` → 失败再 `BluetoothConnectionInsecure` | 要（系统蓝牙里配对） |
| `BLE:AC:3F:...` | `BluetoothLeConnection(mac, ctx)` | **不要**，直接建 GATT |
| `TCP:1.2.3.4[:9100]` | `TcpConnection` | — |

BLE 连接成功后日志会带 MTU（`（BLE，MTU=xxx）`）：BLE 是分包的，MTU 被协商成默认 23
时"打一半"的锅通常就在这里。

## 3. 为什么 BLE 扫描要两路一起跑

只调 Zebra SDK 的 `BluetoothLeDiscoverer` 会踩一个死坑：它按 Zebra 的服务 UUID 过滤，
**固件没广播那串 UUID 的机器永远扫不到**，界面上只有"没找到打印机"，用户完全无从排查。

所以 `print/BleScan.kt` 同时开两路：

- **Zebra SDK 发现**（阻塞、要 Looper 线程）：扫出来的标「Zebra」，是"基本肯定能打"的；
- **原生 `BluetoothLeScanner`**：附近所有 BLE 设备原样列出（名字 + RSSI），非 Zebra 的标「未识别」。
  它能回答最关键的"打印机到底在不在广播"。

两路结果按 MAC 合并，Zebra 的排前面。点任何一台都能连（有的第三方 ZPL 机器就是私有服务，
SDK 不认识但 GATT 能写）。

## 4. 记住上次那台

BLE 打印机**不在系统配对表里**，不记就是每次开机重扫一遍。所以 `print/PrinterPrefs.kt`
把 `BT:<mac>` / `BLE:<mac>` + 显示名存进 SharedPreferences，启动时自动连（开关默认开）。

注入 `--es bt` 时以注入为准，脚本回归不受影响。

## 5. 独立页里的其他东西

- **打印测试页**：60×40 上打型号/链路/MAC + 一维码。换机器、换纸、换现场先打这张，
  比拿业务标签试错省纸；
- **校准（换纸后）**：`~jc`，标签间隙重测，不校准的话每张都偏；
- **打开系统蓝牙设置**：没配对设备时直接跳过去，省得用户自己找；
- **提示文案**：同一台 BLE 打印机同一时间只能被一台手机连着（被别的手机占用时这里会一直连不上）。

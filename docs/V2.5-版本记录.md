# V2.5 版本记录（2026-11-25）

> 主题：**修掉「新装机扫不到附近蓝牙打印机」**（V2.4 现场反馈的权限流程缺陷）+ 收编上一轮未发版的 **dpi 三档支持**（203/300/600）。
> 识别、版面几何、ZPL 生成一律未动 —— 回归判据沿用「常量 12 项断言 + 既有 3 处已知差异基线」。

## 1. 问题现象

`out/label-reprint-V2.4-release.apk` 装到新机器后：点「扫描附近打印机」永远没反应，界面只留一句
「缺少蓝牙扫描权限」；日志里也看不到 `BLESCAN >>> 原生扫描开始`。

**先排除了清单问题**：直接从 V2.4 的 APK 反查合并后的 manifest，
`BLUETOOTH_CONNECT` 与 `BLUETOOTH_SCAN`（带 `neverForLocation`）**都声明着**。
所以不是权限没写，是运行时申请流程走不通。

## 2. 三处真缺陷（都在运行时，不在清单）

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | `scanBle()` 直接调 `BleScan.scan()`，`BleScan` 里只 `checkSelfPermission` → 不通过就返回一句提示 | 扫描按钮**从不申请权限**，界面上没有任何地方能补授权，点了等于原地写一行字 |
| 2 | `onCreate` 里 `cameraPermission.launch(...)` 紧跟 `btPermission.launch(...)` | Android 对并发 `requestPermissions` 会丢掉后一个，回调直接回「拒绝」。**新装机两者都是首次申请，必撞** → 系统根本没弹过蓝牙权限窗 |
| 3 | 只有 `onResume` 之前没有权限复检 | 用户去系统设置手动允许后切回来，界面仍写「缺少蓝牙权限」，看着像没生效 |

## 3. 改法

- **唯一入口** `requestBtIfNeeded(after)`：已授予 → 立刻刷新已配对列表并执行 `after()`；否则发起申请，授予后把动作接回去。全工程不再裸调 `btPermission.launch()`（`afterBtGranted` 保存待续动作）。
- **串行申请**：没有相机权限时只 `launch(CAMERA)`，蓝牙改在相机回调里 `requestBtIfNeeded()` 接着要，两个对话框不再抢通道。
- `scanBle()` → `requestBtIfNeeded { scanBleNow() }`：点一下就自动弹窗并接着扫；`bleScanning` 重入保护提前到入口。
- `onResume` 复检：权限由无到有时重新枚举并清 `bleNote`，日志打 `onResume：蓝牙权限已到位/仍缺失`。
- 打印机页新增红色权限卡（`btGranted=false` 时显示）：**「申请权限」+「打开系统蓝牙设置」**两个按钮，附「若系统不再弹窗：设置 → 应用 → 标签复刻机 → 权限 → 附近的设备」。之前这里是个死胡同。
- 拒绝日志补 `不再询问=true/false`（`shouldShowRequestPermissionRationale` 反推），现场能一眼分清「没弹窗」和「用户拒了」。
- 版本号 `versionCode 25` / `versionName 2.5`（界面仍从 `PackageManager` 读，未写死）。

顺带把 `c85aaf8` 那轮 **dpi 三档（203/300/600）** 一并收进本版发包 —— 那轮改动此前只提交未出包，
现场装机看到 `2.4` 却有 dpi 页会怀疑装错包，故统一提到 2.5。

## 6. 现场排障口诀（写进手册）

1. 点「扫描附近打印机」，**要看到权限弹窗**才算申请通路正常；
2. 弹窗没出来 → 看 `adb logcat | findstr "PRINT"` 那行里的 `不再询问=`：
   - `false`：系统策略还在弹，重装或清权限数据再试；
   - `true`：权限已被永久拒绝，**只能走「设置 → 应用 → 权限」或设备管理侧（Zebra MX/MDM）放行**，代码再改也不会弹；
3. 权限到位后日志应有 `蓝牙权限已到位，已配对 N 台` 与 `BLESCAN >>> 原生扫描开始 8000ms`。

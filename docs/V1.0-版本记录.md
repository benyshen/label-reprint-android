## V1.0 功能范围

链路：

```
拍照/选图 → 标签四边形检测 + 透视校正 → 双引擎条码 + PP-OCRv4 文字
        → 元素表（可改内容/码制、可删） → 自动选模板 → 版面映射（含净空纠正）
        → ZPL → 蓝牙直打 / 导出 .zpl / 复制
```

- **条码**：Zebra AI Data Capture `barcode-decoder` 5.0.4（二维码 + 真包围盒）+ zxing-cpp 3.1.1（一维码兜底）混合引擎
- **文字**：PP-OCRv4 det/rec 端侧（中文；Zebra 模型不含中文 OCR）
- **基准**：`label`（自动找标签四边形并校正；候选面积 ≥92% 画面判为背景）/ `full` / `content`
- **模板**：按标签长宽比自动选（`|ln(图像比/模板比)|` 最小）；用户手动点过则锁定不再覆盖
- **一维码**：`^BC`（Code128）/ `^B3`（Code39）；模块宽下限 2 点；纯数字按 Code128C 算模块数
- **HRI**：与条码同内容且紧贴 → 归并成条码自带明文（`^BC...,Y`），不再单独打一遍
- **文字净空**：与上方条码不足 6 点时下移，并给出告警
- **中文字号**：汉字按 1.0 em 宽、字高 ≈ 字号；硬兜底「宁可小一号也绝不超字段宽」
- **打印**：Zebra Link-OS（先 secure 失败降级 insecure）、已配对设备选择、状态行提示
- **结果页**：`重新识别`（同一张照片重跑整链，不碰相机）+ `重拍`；标题行右侧显示版本号

## 本版修掉的 5 个「纸上与屏幕不一致」的 bug

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 条码/文字整体偏小、位置越往下偏得越多 | 模板选错（60×40 装 70×70 的标签）→ 纵向压到 57%，偏差 −16…−200 点线性放大 | 按标签长宽比自动选模板 |
| 2 | 照带背景的照片时内容只剩一半大 | 基准取了整幅照片（内容只占 239 点宽），模块宽被算成 1 点 | 检出标签四边形 + 透视校正后按标签映射 |
| 3 | 128 码打印后被扫描器读成 39 码 | `^BY1` = 0.125mm，203dpi 下印糊（ISO 要求 X ≥ 0.19mm），扫描器测不准条宽退化判码制 | 模块宽下限 2 点；纯数字走 Code128C 降模块数 |
| 4 | 条码下方 HRI 文字与条码重合 | HRI 既当条码明文又当文字打了两遍，且紧贴条码 | 归并成条码自带明文；净空不足时下移 |
| 5 | 条码下方中文行「挤着叠印」成一团 | 汉字按 ASCII 比值算宽（0.51 em）和字高（0.775）→ 字号偏大 → 超 `^FB` 字段宽时打印机**不是截断而是挤着叠印** | 汉字 1.0 em 宽 / 字高 ≈ 字号 + 硬兜底减字号 |

第 5 条的实测证据（用户那张药品追溯码标签，31 字符行）：

```
修前：^FT131,239^A@N,26,26,E:SIMSUN.TTF^FB416,1,0,L,0^FD药品标识码：8207188 序列号：0078020027464^FS
      → 26 号字实际需要 ≈528 点，字段只有 416 点 → 挤着叠印
修后：^FT131,220^A@N,17,17,E:SIMSUN.TTF^FB416,1,0,L,0^FD约品标识码：8207188序列号：0078020027464^FS
      → 实印宽 ≈343 点 ≤ 416，留 18% 余量
```

## 已知问题（V1.0 不修，留待后续）

1. **APK 450 MiB**：debug 未压缩 + 含 16MB 模型资产 + 18MB 样图。正式分发需 release + minify + 剥离样图。
2. **DL 引擎一维码在糊图上解不出**（<≈4 px/模块时检测到但 value 为空）→ 由 zxing 兜底；纯 DL 方案不可行。
3. **OCR 误差**：长数字串偶发丢尾字符（`…0078020027464` → `…007802002746`）；形近字误识（药→约）。
   依赖元素表的「点一下改内容」兜底，未做自动校验。
4. **模板只有 3 种**：标签长宽比与模板差异大时取最近比值，绝对尺寸会偏。
5. **无自动验收**：识别结果需人工确认；未做「打完再拍一张自动比对」。

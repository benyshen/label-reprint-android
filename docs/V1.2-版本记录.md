## 2. 二维码与其下方要素多留 1mm

**需求**：QR 打出来后，和它后面的要素之间增加 1mm 间距。

**实现**：`ZplGeometry.QR_TEXT_GAP = MIN_TEXT_BARCODE_GAP(6) + mm2dots(1.0) = 14 点 ≈ 1.75mm`；
一维码仍走 6 点（HRI 贴着条是码制规范，不该加）。

### 2.1 顺手挖出的两个坑

**(a) "元素框底"不是"印出来的底"。** 净空原本按 `element.dots[3]`（照片里量到的墨迹底）算，但 ZPL 的
`^FT` 对二维码锚的是**符号（含 4 个模块 quiet zone）的下缘**：

```
^FT y = round(框顶) + 黑模块高 + 4 × mag        // anchorDyQr
```

实测那张测试标签：框底 135 点，实印下缘 **163 点** —— 差 28 点（3.5mm）。也就是说按框底加净空永远算少，
纸上就是文字压进 QR 的 quiet zone。现在两端都改成 `printedBottom()`：二维码用 `qrLayout()` 算实印下缘，
一维码用 `顶 + 条高`。

`qrLayout()`（新增）把 mag / 黑模块高 / 锚点偏移收进 `ZplGeometry` 一处，`ZplBuilder` 和净空计算共用 ——
两处各写一份 mag 算法迟早漂移，而净空算错就是文字压码。

**(b) 旧逻辑把"压在条码里"的文字直接跳过。** 原判据 `if (文字顶 < 条码框底) continue`，本意是"不碰条码上方的文字"，
但"文字已经压进条码"这个最该修的case 也满足该条件 → 被静默跳过。现在改成
`if (文字底 <= 条码框顶) continue`（整行都在条码上方才不管），压在条码里或在其下方都要让出净空。

新增 `tools/make_qr_gap_label.py`：造一张 QR 下方 4px（≈0.1mm）就贴文字、再下面放一维码 + 紧贴 HRI 的测试标签
（`assets/samples/qr_gap_test.png`），用来验证"QR 加间距、一维码不动"。

### 2.3 没做的部分

"每个打印要素之间都加 1mm" **没有做** —— 只按最新要求给了二维码。理由：一维码的 HRI 必须贴条（间距大了
人眼读串会和条错行），而文字与文字之间加间距会整体撑开版式，容易把最下面的要素顶出标签。
真要全局加，改 `deCollide` 的 `gap` 选择即可，但需要先确认纸上效果。

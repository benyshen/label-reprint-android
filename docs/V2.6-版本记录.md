# V2.6 版本记录（2026-11-25）

> 主题：**修掉 ZR668 上「发送打印任务时报 NPE」** —— 根因不在我们的 ZPL、也不在打印数据，
> 而是 Zebra Link-OS SDK 的状态查询接口在这台固件上解引用空指针。

## 1. 现场现象

蓝牙连上 ZR668（`ZR668·XXZKJ183904489` / `AC:3F:A4:EE:9E:F1`）后点打印，界面报：

```
Attempt to invoke virtual method
'java.lang.String java.lang.String.replaceAll(java.lang.String, java.lang.String)'
on a null object reference
```

## 2. 根因（把 SDK 的 class 反汇编看出来的，不是猜的）

`com.zebra.sdk.printer.internal.PrinterStatusLinkOs`：

```java
// getStatusInfoFromPrinter()：发的是「JSON 方式」的 getvar，不是 ~HS
printerConnection.sendAndWaitForValidResponse(
        "{}{\"device.host_status\":null}".getBytes(),
        maxTimeout, timeToWaitForMoreData, new JsonValidator());

// parseJsonStatusResponse(String json)：
String hs = (String) StringUtilities.convertKeyValueJsonToMap(json).get("device.host_status");
String s  = hs.replaceAll("\\r\\n", "\n");     // ← hs 为 null 时直接 NPE，SDK 没判空
```

即：**固件不支持 `device.host_status` 这个键**（ZR668 / V86.20.21Z 实测如此），
打印机回的是 `{"device.host_status":null}`，SDK 取出来是 null，然后对它调 `replaceAll` → NPE。

NPE 原文之所以会显示在界面上，是因为我们自己的 `status()` 把所有异常都塞进
`humanReason()`，而 `humanReason` 对认不出的异常**原样返回 message** —— 于是 SDK 的
Java 堆栈文案就这样露在了状态卡里（看着像打印失败，其实打印链路是好的）。

## 3. 改法

| # | 改动 | 为什么 |
|---|---|---|
| 1 | 状态读取改走 **ZPL `~HS`**（`PrinterStatusZpl(c)`，public 类，自己解析主机状态串），只在它失败时才退回 Link-OS 的 JSON 接口 | `~HS` 是 ZPL 标准命令，不碰那个会为 null 的 JSON 键；我们连接后第一件事就是强制 ZPL 语言，这条路径对现场所有机型都成立 |
| 2 | 抽出 `readStatus(c)` 一处实现，`status()`（5s 轮询）与 `printZpl()`（打印后缺纸/开盖判定）共用 | 两条路径原来各调一次 `currentStatus`，改一处漏一处就还会崩 |
| 3 | 状态读不到时给 **"状态不可用（该固件不支持状态查询；不影响打印）"**，不再把异常原文当状态显示 | 状态查询失败不等于打印失败，界面不该这么暗示 |
| 4 | `humanReason` 增加 NPE 分支，翻成"状态查询不可用、不影响打印、要看状态用面板" | 现场要的是"我该怎么办"，不是 Java 堆栈 |
| 5 | 打印失败日志补 `t.javaClass.name` + 前 6 帧堆栈（原来只有 message） | 这轮就是靠反汇编才定位的；日志里有类型和帧，下次不用再反汇编 |

## 4. 验证

- `./gradlew compileReleaseKotlin` → 通过；`assembleRelease` → 出包。

## 6. 现场验收要点

1. 连上后状态卡应显示 **"就绪"**（或具体的缺纸/开盖），不再出现 Java 异常原文；
2. 日志里若出现 `~HS 状态读取失败(...)，退回 Link-OS JSON 状态`，说明 `~HS` 这条路也不通，
   把那一行发我 —— 那就要改成自己发 `~HS` 原始读字节解析，而不是用 SDK 的状态类；
3. 打印是否真的出纸，看 `PRINT >>> 成功 <N> ms｜BT:…` 这一行（在它之前的是发送，之后的才是状态判定）。

# V1.3 版本记录（2026-10-17）

结果页「打印」区从**一行随时被覆盖的状态字符串**改成一个**打印机状态卡片**：灯色 + 型号 + 实时状态 + 设备选择 + 刷新/重连。

---

## 1. 为什么改

旧实现只有一个 `printerState: String`，所有消息往同一格子里写：

```
"连接中…（BT:AC:3F:…）" → 连上后 "已连接 ZR668 · 就绪"
                        → 打印一次 → "已发送（578 ms）"     ← "就绪"被顶掉
                        → 再来一次 → "打印失败：打印机缺纸"  ← 又和链路状态混在一起
```

三个后果：
1. **看不出现在能不能打**：最后一句话是"已发送 578 ms"，但打印机此刻可能已经缺纸/开盖。
2. **状态只在连接那一刻读一次**：之后不管换纸、开盖、暂停，界面永远显示连接时那句"就绪"。
3. **"选中的打印机"没有视觉反馈**：已配对设备只列成一排 chip，点了哪个看不出来。

## 2. 现在的样子

`ui/PrinterCard.kt`（新）—— `PrinterUi` 数据类（`LinkPhase` + 目标地址 + 名字 + 型号 + 详情 + 时间戳），
卡片布局：

```
● 已连接   ZR668 · XXZKJ184301333              刚刚
AC:3F:A4:F2:56:2F
就绪
[ XXZKJ184301333 ]                      ← 选中的 chip 绿底黑字
[刷新状态] [重连]
```

| 档位 | 灯色 | 何时 |
|---|---|---|
| `IDLE` 未连接 | 灰 `#9A9A9A` | 冷启、还没选打印机 |
| `CONNECTING` 连接中… | 蓝 `#0073E6` | 点设备 chip / 重连 |
| `CONNECTED` 已连接 | 绿 `#A8F931` | 连上且状态查询正常 |
| `ERROR` 连接失败 | 红 `#FF6B6B` | 连不上、缺纸、开盖、暂停、发送失败 |

其它细节：
- **型号优先于蓝牙名**：配对名常是 `XXZKJ184301333` 这种出厂串，型号 `ZR668` 才是人想看的（名字仍显示在后面，chip 用名字）。
- **chip 用 MAC 判定选中**，不用名字 —— 车间里两台同名打印机很常见。
- 右上角"刚刚 / 12s 前 / HH:mm:ss"是**详情的时间**，不再是日志文案。
- 没连上时"刷新状态"禁用（没意义），"连接/重连"可用。

## 3. 每 5 秒自动问一次状态（关键改动）

```kotlin
LaunchedEffect(printerUi.phase) {
    if (printerUi.phase != LinkPhase.CONNECTED) return@LaunchedEffect
    while (isActive) {
        delay(5_000)
        if (!printing && !busy) refreshPrinterStatus()
    }
}
```

配套两件事，缺一不可：

**(a) `PrinterGateway.status()` 也拿同一把 `lock`。** 原来是裸读 `currentStatus`，而轮询是后台协程 ——
一次 ZPL 发送（`c.write()` + 400ms 等待）中间被插进一次状态查询，蓝牙串口上的读写就交错了，
成纸可能只打一半。现在状态查询与打印/连接/SGD 全部串行在同一把锁上。

**(b) 打印中、识别中跳过轮询**（`printing` / `busy` 两个 flag）。锁能保证不交错，但没必要在打印瞬间
再排一条查询进去占时间。

> 为什么不做得更"实时"（比如 1s 一次）：状态查询是**主动问打印机**（SGD 往返，蓝牙下实测量级 0.3~1s），
> 5s 已经能覆盖"换纸/开盖"这类人工操作；更密只是白耗电和占链路。"我刚换了纸，立刻要看"走"刷新状态"按钮。

## 4. 真机验证（TC73 → ZR668 @ AC:3F:A4:F2:56:2F）

```
PRINT >>> 已连接 ZR668（BT:AC:3F:A4:F2:56:2F）状态=就绪
PRINT >>> 状态刷新：就绪（alive=true）        ← 之后每 5s 一条
```

三张截图（`shots/`）：

| 状态 | 截图 | 实测表现 |
|---|---|---|
| 已连接 | `v13_printer_connected.png` | 绿点 · 已连接 · `ZR668 · XXZKJ184301333` · 就绪 · "刚刚" · 两按钮可用 |
| 连接失败 | `v13_printer_error.png` | 红点 · 连接失败 · 地址 `00:11:22:33:44:55` · 失败原因原文 · 刷新状态灰掉、连接可用 |
| 未连接 | `v13_printer_idle.png` | 灰点 · 未连接 · 型号行留空 · chip 可见 · 两按钮禁用 |

失败场景是用 `--es bt 00:11:22:33:44:55`（一个不存在的 MAC）注入的，日志确认是真实 SPP 失败：
`蓝牙链路建不起来（SPP 套接字失败）…`。

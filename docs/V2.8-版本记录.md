# V2.8 版本记录（2026-11-26）

> 主题：**去掉连上打印机后每 5 秒一次的状态轮询** —— 现场观察「连上后一直有数据交互」的直接成因。

## 1. 问题定位（代码位置）

`MainActivity.kt`（V2.7 及之前）里有这么一段：

```kotlin
LaunchedEffect(printerUi.phase) {
    if (printerUi.phase != LinkPhase.CONNECTED) return@LaunchedEffect
    while (isActive) {
        delay(5_000)
        if (!printing && !busy) refreshPrinterStatus()   // → printer.status() → 向打印机发状态命令
    }
}
```

`refreshPrinterStatus()` → `printer.status()` → 官方 `PrinterUtil.getCurrentStatus(...)`（内部是 `~HS` 往返）。
所以**只要处于「已连接」状态，就每分钟往蓝牙链路发 12 条状态命令**，这就是观察到的"一直有数据交互"。

三个放大问题：

| # | 问题 | 后果 |
|---|---|---|
| 1 | **没有生命周期门控** | Compose 的 `LaunchedEffect` 在 Activity 进后台后**继续执行**（composition 未销毁）→ 锁屏/切后台仍在每 5s 敲打印机 |
| 2 | 状态通道被轮询带着反复 open | V2.7 引入的 `BluetoothStatusConnection` 每次查询都会 `if (!isConnected) open()`，掉线时每 5s 重连一次，噪声更大 |
| 3 | 失败退避只 60s | ZR668 答不上状态查询 → 3 次失败后暂停 60s → 又试 3 次，形成周期性突发，等于链路永远在被敲 |

## 2. 改法

| 项 | 现在 |
|---|---|
| 周期轮询 | **整段删除**。状态只在三种时机查，全部按需：① 连接成功后一次；② 用户点「刷新状态」；③ **打印失败时一次**（用来补出缺纸/开盖/暂停原因） |
| 打印成功 | **不查状态**（沿用 V2.7 的结论：发完立刻查会把作业吃掉） |
| 复制退化 | 状态连续失败 3 次 → `statusDisabled = true`，**彻底停用自动查询**，界面提示「状态查询已停用（该固件答不上来，点「刷新状态」可强制再试）」 |
| 手动刷新 | `status(force = true)`：清掉停用标记并强制重试一次 —— 换纸/换盖后想看状态，点一下即可 |
| 重连 | 连接成功时复位停用标记与计数 |

删除后全工程只剩一处 `delay()`：`QuadCropPane` 的 3 秒放大镜看门狗（纯 UI，不碰蓝牙）。

## 5. 验收

1. 连上打印机后**静默**：日志里应只有连接那几行（`connected: …`、`状态通道：…`、`状态刷新：…`），
   之后没有周期性输出；蓝牙抓包/打印机指示灯也不该再持续闪。
2. 点「刷新状态」→ 日志出现 **一行** `PRINT >>> 状态刷新：…`，然后继续静默。
3. 打印 → `PRINT >>> 成功 N ms`，**不发状态命令**；打印失败时才额外有一条状态查询。
4. 若状态一直答不上来，第 3 次之后界面显示「状态查询已停用…」，此后不再有任何状态流量。

## 1. 上一版为什么偏上（真因，不是"看起来")

V1.4 的裁剪用了 `Image.getbbox()`。它对 RGBA 只要**任一通道非零**就算内容，而抠图后源图四周还留着
`alpha 16~31` 的极淡残影（原图黑底其实是 `(8,6,8)`，不是纯 0）。结果裁剪框被撑到 `(52,321)-(2048,2048)`：

| | 裁剪框 | 实际画面 |
|---|---|---|
| 宽度 | 1996 px | 1386 px |
| 高度 | 1727 px | 1252 px |
| 位置 | 顶边贴住画面顶（y=321） | 主体整体偏上，下方一大片空黑 |

主体只占到高度的 72%，且紧贴框顶 → 屏幕上就是"画面偏上 + 下方黑边大"。

**修法**：按 `alpha ≥ 32` 生成掩膜再取 bbox，只框真正可见的墨迹（1386×1252）。这一步是根因修复，
跟"放大"是两件独立的事。

## 2. 顺便把黑区缩小

官方 72dp 安全区是"任何遮罩都不切"的**最保守**取值，实际用起来四边留黑太多。查了这台 TC73 的
启动器（`com.android.launcher3`）用的是**圆角方形**遮罩，圆角约占 20~25%，所以：

| | V1.4 | V1.5 |
|---|---|---|
| 主体尺寸 | 76 × 68.8 dp | **84 × 76 dp** |
| 四边留白（dp） | 左16 上19.5 右16 下19.8 | 左12 上16 右12 下16 |
| 主体面积 | 1× | **+36%** |

84dp 的依据：圆角方形遮罩（r = 25% × 108 = 27dp）时，内容框角点到圆角弧心的距离
`√((27-12)² + (27-12)²) = 21.2 < 27` → 四角仍在遮罩内。

**代价**：若某个启动器用**正圆**遮罩，相机左上角 / 袋子右下角会被啃掉约 3~5dp
（圆可见半径 54dp，84dp 方框对角线半径 59.4dp）。那两处本身就是圆角，视觉上基本看不出；
但这台机器的启动器不会是正圆，所以按 84 交付。

## 4. 一个教训（写进脚本注释了）

**不要用 `getbbox()` 定抠图的裁剪框**——RGBA 的 getbbox 对"1/255 的残影"也当真，一张 2048 的画布上
这点残影足以让裁剪框多出 600×475 px，主体立刻跑到一角。要么先把小于阈值的 alpha 归零（这里 `<0.06`），
要么显式用 `alpha >= 32` 的掩膜取框。
